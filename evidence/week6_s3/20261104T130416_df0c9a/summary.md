3,000건/초 단계에서 전처리 중앙값은 **0.36초**, 업로드·검증 중앙값은 **4.96초**였다.

**시간을 가장 많이 쓰는 구간은 순차 S3 업로드·체크섬 확인이다.** 이번 입력 범위에서 실제 처리 한계에 도달했는지는 전체 backlog 시계열과 함께 판단해야 하며, S3 서비스 자체의 최대 성능을 측정한 것은 아니다. 각 단계의 마지막 배치는 다음 시간 구간에 완료될 수 있어, 표의 완료 처리량이 입력보다 약간 작아도 곧바로 유실을 뜻하지 않는다. 최종적으로 단계별 입력과 정상·오류 저장 건수를 모두 대조했다.

미완료 건수에는 최대 20,000건을 모으는 정상 대기도 포함된다. Kafka/Spark 방식의 처리량·지연과 측정 경계가 다르므로 개선율로 직접 비교하지 않는다. 이번에는 컨테이너 없이 노트북 Python과 AWS CLI를 사용했고, 실험 앞부분에는 요청한 실제 600초 수집도 함께 실행했다.
