# 7주차 B안 실험 계획

2026-11-08, 실행 전에 작성.

- 가설: 30초 trigger에서 maxOffsetsPerTrigger=10,000은 읽기 상한 약 333건/s를 만든다. 600건/s 입력을 처리하기 위해 상한만 50,000으로 올리면, 배치 시간이 30초 미만인 조건에서 누적 백로그가 줄고 측정 p95가 60초 미만으로 낮아질 것이다.
- 동일 조건: 100건/s 워밍업 60초 후 drain, 600건/s 측정 120초 1회 후 drain. 전후 별도 Kafka 토픽/체크포인트/S3 prefix, 파티션 3, Spark local[2], driver 1g, 컨테이너 2g, shuffle 2, trigger 30초.
- 입력: 동일 생성기와 payload 분포. 실행 ID와 실제 발생 시각은 각각 새로 생성한다. 전후 각 78,000건(워밍업 6,000 + 측정 72,000).
- 변경 변수: WIKI_MAX_OFFSETS 10,000 → 50,000. 나머지 처리 코드와 저장 방식은 고정.
- 결과: ACK 실측 입력률, 구간 commit 처리률, p50/p95, lag 추세, Spark 배치 시간, callback 시간 분해, ID 누락·예상 밖 ID·offset 중복.
- 제한: 각 1회, 고정 입력률 한 점의 비교. 최대 처리량/장시간 안정성/통계적 유의성을 확정하지 않는다. 노트북의 다른 컨테이너는 중지하지 않고 환경 기록에 남긴다.
